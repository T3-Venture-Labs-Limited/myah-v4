## 1. Outcome, evidence and scope

When a Campaign create commits but delivery of its response fails, recover the exact saved Campaign after Twenty's native retry receives a duplicate. Open that record, reconcile native data and release controls without reload. A duplicate message alone is never proof. The original local evidence establishes this conditional defect, not production frequency or equivalence to historical MYAH-323.

Recovery is **Campaign index creation only**, inside the existing index/create/Apollo seams. Creator membership, other objects, relation creation, activities and Workflow remain compatibility coverage, not recovery targets. No generic callback, replay or completion framework; no backend change, server ledger, new dependency, retry-policy rewrite or global auth/toast redesign.

Parent-approved policy replaces all pending choices in revision 1: one unresolved Campaign per workspace+actor within a continuously authenticated in-memory session; immutable generated ID and original sanitized input; user retry reads first and can resend the same input/ID only after authoritative null; retain uncertainty across resends; preserve origin as data, not callbacks; guard real authenticated forwarding and inbound delivery; distinguish saved from refresh failures. Standard UUID uniqueness is accepted, not mathematical insertion-ownership proof.

**Additional explicit supervisor approval during this revision:** Campaign index creates defer optimistic shell/list insertion until persistence is verified. Use native `mutate({fetchPolicy:'no-cache'})`, no `optimisticResponse` and no `update` callback in that branch. Keep visible pending feedback. Default/non-Campaign optimistic behavior is unchanged. This small transient timing change eliminates speculative-shell rollback/SSE ownership complexity; it is not permission to skip identity guards or audits.

**Additional conditional supervisor approval:** the existing aggregate-refresh hook may take a narrow optional Campaign context. Its default `refetchQueries` behavior stays unchanged. Campaign-initiated refresh snapshots the same active aggregate observables/documents/variables, performs guarded strict no-cache reads and guarded native `writeQuery`, without mutating watcher options. This closes aggregate-response normalization after a workspace/session switch; partial/error-bearing results never write. Both audits must verify this remains a small optional branch.

**Additional supervisor-approved ordering detail:** the native create-list effect may accept optional `creationPosition:'first'|'last'`, only as a transient insertion-order hint after authoritative filter evaluation and only for lists without explicit sorts. Authoritative node/fragment/store/group values remain numeric. Existing explicit view sort wins, default callers remain unchanged. The plan consolidates these three opt-ins (create, aggregate refresh, list insertion); audits must judge their total complexity against the rollback complexity removed.

## 3. Frozen attempt, origin and lifetime

The exact types and file owners are in plan §2. State is one native nonpersistent Jotai state containing a bounded map (at most one unresolved entry per workspace+actor/session), not an atom family with unbounded historical UUID keys. Each attempt stores immutable JSON input (the exact sanitized wire payload), immutable record ID, workspace/user/userWorkspace/impersonation identity, metadata ID, origin descriptor, uncertainty, phase and optional verified node/warnings. No raw token, callback, promise, Apollo client or navigation closure is stored in attempt state.

Origin data: `recordIndexId`, `contextStoreInstanceId`, `returnPath` (same-origin pathname+search+hash), frozen open-in choice, `shouldCloseAfterCreation`, position, and the original group-field metadata ID. Mount counts for Campaign origins live in the same state; a Campaign-only effect in the existing surface creation-options effect registers/unregisters an origin. Transient command unmount does not unregister the index or discard an attempt. Completion checks both mounted original index and current returnPath before navigation or original grouped-ID changes.

A different origin's New action does not mint an ID, read, resend, virtualize, invoke a callback, or navigate automatically. Show “A Campaign creation is pending in another view. Return there to continue.” Native snackbar action “Return to original view” performs a guarded client-side navigation to the stored relative path. It does not retry. If a nested origin is no longer mounted at that path, tell the user to reopen that original view; no fallback create in another context. On the original origin, New checks the retained attempt. This also applies when a saved response arrives after the user leaves: retain saved ID, no surprise navigation; original origin's next action opens the saved record.

**Session lifetime:** starts when the core provider observes a valid native ACCESS-token actor and current authenticated user. Same actor token renewal does not end it. An in-SPA workspace switch keeps per-workspace attempts for the same actor but invalidates the active operation boundary; returning explicitly checks the retained ID. Logout/token loss, workspace-agnostic token, actor/impersonation change, core-provider teardown or Jotai-store reset ends this session, increments generation and clears attempts. All old operations fail closed even if the same actor signs back in. Workspace/current-user/token subscriptions are synchronous `store.sub` listeners installed by one Campaign session sidecar under `ApolloCoreProvider`; React effects are not dispatch guards. In-flight identity mismatch latches invalidation, not merely equality at return time. Native `useAuth.clearSession` sets tokenPair null before redirect; native renewal writes that atom. Direct same-document localStorage changes are also checked at each dispatch/response; arbitrary undetectable ABA writes outside native auth are not a supported session API.

Full reload, tab/device sharing, workspace-domain/full-page redirects and fresh login continuity are **out of scope**. Do not promise retained UUID across them. In-memory origin navigation uses the router (not a document reload). After a reload the user should inspect the saved Campaign list; this fix does not install durable idempotency storage or an abandon-and-fresh-create action.

## 4. Transition table

An operation holds a synchronous run-number lease before any preparation/await. A concurrent action returns undefined and a deduped “Campaign creation is already in progress.” Pending feedback appears when the owner starts, since no speculative row is inserted. It is removed when the owner settles. The lease is released in finally, with compare-by-run checks so an old promise cannot clear a newer owner.

| Current state / input | Operation | Result / retained state |
|---|---|---|
| No attempt; explicit New at Campaign index | Reserve preparing slot; generate UUID once; sanitize/serialize merged input with ID last | creating; 1 native mutate (max 2 transport attempts) |
| Preparation throws before dispatch | No mutation/read/cache write | Clear slot; friendly error; pending/loading false |
| creating; valid exact normal response | Mark saved before any cache/event work | Reconcile once, open original target, clear on successful navigation |
| creating; first-response genuine duplicate/validation/auth failure, no uncertainty | No readback, no cache shell | Clear; friendly genuine error; a later corrected New is a new attempt |
| creating; eligible transport delivery failure | Mark uncertainty on this attempt (including final attempt) | Native retry unchanged; final transport error or narrow duplicate permits one exact read |
| creating after uncertainty; terminal known validation/auth/403/413 | Never turn known rejection into success or read it as a duplicate | Retain unconfirmed original attempt; friendly genuine error, no automatic read/resend |
| initial recovery read = exact readable node | Verify under current identity/permission | saved; same completion as normal response |
| initial recovery read = authoritative null | **No automatic extra mutation** | unconfirmed; show explicit retry explanation |
| initial recovery read = offline/forbidden/partial/invalid/null-with-errors | No absence proof | unconfirmed; no mutation |
| unconfirmed; original-origin explicit New | Read exact retained ID first | Same input/ID, no new UUID |
| user retry read = exact readable node | Recover | saved |
| user retry read = error-free authoritative null, create currently allowed | This user action authorizes one same-ID/unchanged-input native mutate | creating; native max=2; retain prior uncertainty |
| user retry read = null but no current create permission | No mutation | unconfirmed; permission error |
| resend's first response = duplicate while attempt already uncertain | One exact authorized read (even without new transport failure) | saved if exact; else unconfirmed |
| unconfirmed retry read offline/denied/ambiguous | No mutation, no fresh ID | unconfirmed; actionable error, controls settle |
| any unresolved attempt; different origin New | Return-to-origin snackbar only | State unchanged |
| pending; identity/workspace boundary invalidated | Reject stale dispatch/next/error before normalization, uncertainty recording or native error callbacks | Nonretryable local BoundaryError; no read/resend/toast/cache/store/event/navigation; retain unconfirmed in old workspace if session survives |
| saved; cache/list/store/group/event/aggregate step fails | No rollback, no recovery mutation, no membership replay | Open saved target; truthful refresh warning; if origin unavailable/navigation fails retain saved node |
| saved retained; original-origin New | Current authorization + exact read if boundary changed; open saved ID only | Never resend, even if read now returns null; retain saved on failure |
| success navigation completes | Clear attempt and pending message | Later intentional New generates a new UUID |

“Could not confirm whether the Campaign was saved. Choose New to check it and retry the same creation if it is absent.” is the localized uncertainty message. Known errors use native `enqueueErrorSnackBar({apolloError})`. Identity invalidation never toasts in a new workspace/session. No automatic loop: each dispatch group is one native mutation (max two transport requests); each failed mutation can trigger at most one native query (max two transport requests). Only another user action can start another check/resend group.

## 5. Authorization and proof boundary

Operation context key is **`campaignCreation`**, explicit second-argument opt-in at `createOneRecord`. Only the Campaign index passes it; no duck-typing IDs or enabling all Campaign mutation consumers. It carries exact expected identity, session/boundary/run numbers, operation kind and per-operation transport evidence plus the originating Jotai store. The actual types and guard function signatures are frozen in the plan.

At async auth header construction, check selected token identity. Immediately downstream of RetryLink, before **each** transport forwarding, check both actual Authorization header identity and current localStorage token identity, current Jotai workspace/user/member, live attempt lease, session/boundary generation and current object permissions. The current tokens need not be byte-equal after same-identity renewal. Ownership uses workspace+actor/session, not optional member claims. A new **explicit** retry captures the current full native identity/permissions and requires the retained workspace+actor; membership/permission changes do not permit a new UUID or changed input. Each operation's expected full identity is then fixed until it settles. Do not accept workspace-agnostic/API tokens. Before each inbound `next` **and at the start of inbound `error`**, perform the same checks. On mismatch throw nonretryable `CampaignCreationBoundaryError` before recording transport uncertainty or forwarding the original error; RxJS tap replaces the stale error with this local error. Invalid payloads never reach native HTTP/GraphQL error classification or Apollo normalization. At ErrorLink callback entry, an opted-in Campaign operation's existing BoundaryError returns immediately without native callbacks, preserving rejection. Every other opted-in Campaign error must recheck identity/header/lease before native classification: RetryLink awaits even a false retryIf result, allowing identity to change after downstream tap.error passed. If the entry check fails, return an RxJS `throwError` Observable with BoundaryError; do not throw directly from ErrorLink's observer. This bypasses `onNetworkError`, `onPayloadTooLarge`, `onErrorCb`, auth renewal and other native UI callbacks for the invalidated operation while preserving its rejection. Default operations bypass the check; current-identity Campaign errors retain native treatment. Current-session HTTP413 still rejects status413 and calls `onPayloadTooLarge` exactly once; current-session network errors still reach `onNetworkError` normally. Recheck before normalization, store/event and navigation; recheck after aggregate await. ErrorLink renewal may run native renewal but may not forward a stale Campaign operation. The guard never writes/refreshes credentials and does not authorize access on behalf of the server.

A successful strict native mutation or strict native exact-ID query returns an object with `id === attempt.recordId`, `__typename === 'Campaign'`, `deletedAt === null`, and complete data for the actual generated selection (including nested selected properties). Validate selected core scalar fields explicitly: Name/Objective string|null, position number|null, createdAt/updatedAt string, with their metadata nullability; retain other generated native field values without introducing an all-object schema-validation framework. Include `id`/`deletedAt` in opted-in selection; metadata must expose them. Query partial data+errors, missing fields, wrong type/ID, deleted node and missing response property are ambiguous, not success/null. Nullable Name and Objective are TEXT, not full-name/rich-text shapes. Validate the complete selected node, not unrequested relations. Native permissions shape the query; never request fields denied now merely because the original input used them. If required identity/deletion fields are no longer readable, confirmation is unavailable. Server permissions/RLS still apply to every request.

Eligible uncertainty is observed **after actual create forwarding** at the downstream link: fetch `TypeError`, dispatched `AbortError`, `ServerParseError`, or `ServerError` status>=500. GraphQL error payloads are not transport uncertainty. Other thrown exceptions, local preparation/cache/navigation errors, HTTP401/403/413 and known GraphQL validation/auth errors are not eligible. Unknown/malformed mutation results after a dispatched request retain unconfirmed state but never become authority or blindly resend. Duplicate eligibility additionally requires retained uncertainty; accept subCode `DUPLICATE_ENTRY_DETECTED` or the observed exact BAD_USER_INPUT duplicate message. A fresh duplicate never triggers a read even if a preexisting exact-ID row exists.

## 6. Saved versus completion, cache and failures

For Campaign only, native mutation/read both use no-cache and no update callback (installed Apollo QueryManager explicitly sets CacheWriteBehavior.FORBID for no-cache mutations). After strict response validation and current-boundary check:

1. Store verified node and phase `saved` synchronously. This is persistence proof, independent of UI completion.
2. Write authoritative flat record through existing `useCreateOneRecordInCache` fragment primitive. Do not call reference-only list effects first. Treat undefined cache return as a refresh failure.
3. On successful fragment write, invoke `triggerCreateRecordsOptimisticEffect` with authoritative node, **`checkForRecordInCache:false`**, existing permissions and `shouldMatchRootQueryFilter:true`, then upsert authoritative flat record in native store. No speculative row exists: use native create/attach semantics (`currentSourceRecord:null`), not update/diff against the fragment just normalized. This restores Campaign.owner → WorkspaceMember.ownedCampaigns inverse cache/store attachment, including retained ownerId from defaults/filters. Native attach dedupes a prior SSE/native attachment without detach, eviction or completion replay; no new relation framework. Existing list/group-by primitive dedupes an SSE-preinserted ID; the optional insertion hint applies first/last only to unsorted root lists after numeric filter evaluation, never to the authoritative node or group dimensions. Explicit view sorts use authoritative fields. Explicit index group arrays must filter out this ID before prepend/append using **original** position.
4. Attempt active aggregate refresh via `useRefetchAggregateQueries` only. The Campaign optional branch snapshots exactly the active aggregate observables selected by native names, uses their exact documents/variables with strict guarded no-cache reads, then checks the boundary and writes native query results only if that observable is still active with the same scope. Do not change watcher options, issue a second refetch after write, or write partial/errors. Default callers retain native refetchQueries. No broad/all/inactive refresh; successful writes supply real absolute counts, not fake callback success.
5. Attempt native create browser event once per verified attempt. Mark completion attempted before entering this bounded sequence; no replay after a partial throw. Browser listeners' asynchronously reported errors are not detectable receipts; no claim that all event consumers completed.
6. Open/retain the saved Campaign using original native destination. If steps 2–5 fail, still open it and show “Campaign saved, but some data could not refresh. Reopen the Campaign or refresh this view.” Aggregate failure has the more specific “Campaign saved, but counts could not refresh.” Do not claim count freshness. Each independent bounded step catches failures; failed normalization skips list insertion rather than creating dangling references, but does not prevent a best-effort store upsert/aggregate/event/navigation.
7. Only successful authorized original-origin navigation clears the attempt. Navigation failure retains `saved` and offers opening the same record next time; it never creates again. Reopening uses native record-page reads, not replaying completion steps. Different origin or authorization loss retains saved without running callbacks or navigating. No optimistic rollback/eviction of a verified or independently SSE-inserted save.

Default `createOneRecord` return/reject, explicit field selection, skipPostOptimisticEffect, optimistic writes and generic callback behavior remain unchanged except loading finally (including preparation failures). Non-Campaign index rejections remain unchanged. The only shared table caller consuming the returned record adds an `isDefined` guard before store/virtualization; other callers ignore the Campaign handled undefined.
